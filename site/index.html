How it works · Relate is the engine

Delete, re-run, roll back. Hundreds of times a second.

Every trial is a transaction

Delete a set of relationships inside a Relate transaction, re-run your query, compare, roll back. Only deletions that keep the answer are applied, on a scratch copy; the source is never opened for writing.

EXPLAIN prunes first

Witness collects the labels and types named in the query and in Relate's EXPLAIN plan. :ON_CONTINENT is in neither, so 3,504 relationships go in one verified step, before trial 3.

Honest by design · what the stamp does not say

Deletion-minimal. Not smallest.

  1. 1
    Deletion-minimal means: no single remaining relationship (or kept isolated node) can be removed without changing the answer. It does not mean "smallest possible".
    README · The Solution
  2. 2
    Because a query with NOT EXISTS or aggregation is not monotone, a witness proves its own answer on its own file; it does not prove that every superset of it gives the same answer.
    README · The Solution
  3. 3
    The gap mostly reflects an embedded engine versus a Dockerised server with a network round trip per statement; it says nothing about Neo4j's query engine.
    README · Measured against Neo4j

Questions a judge would ask

Before you clone it.

Is the witness the smallest subgraph that gives the answer?

No. It is deletion-minimal: no single remaining relationship can be removed without changing the answer. A smaller witness may exist.

What counts as changing the answer?

The answer is compared exactly: types matter, rows are a bag (order is not part of the answer), floats to 12 significant digits, and this headline run compares lists strictly (--strict-lists). Pulling exhibit 4 keeps all four airports but drops US from two rows, and that is a change.

Does Witness ever write to my graph?

No. The source .rl is copied byte for byte and never opened for writing; every reduction checks its SHA-256 unchanged afterwards. Fixture mode pulls from Neo4j once and never pushes back.

Is anything mocked?

Not the judged path: the graph store, transactions, rollback and queries are real Relate in every test. In tests, relate pull (it needs a Neo4j server) is stood in, and a few tests substitute timers, process calls, a failing CLI, a database wrapper that injects engine faults, or one reducer phase to reach rare branches. The committed fixture run pulled from a real Neo4j server (fixtures/mex-foreign.report.json).

Why Relate rather than a Neo4j server?

The inner loop is one transaction per trial, in process, on a single file: 366.8 trials/s here against 90.2 over Bolt to Neo4j in Docker on the same machine. And a witness is a file you can commit, hand over and open with plain relate, with no server.

How does an agent use it?

Over MCP. The why tool returns the witness of the agent's own answer and check re-proves it. Two recorded sessions are committed: evidence/mcp-transcript.md (a scripted client) and evidence/mcp-agent-session.md (a real model, claude-sonnet-5-5 in Claude Code, writing its own Cypher and attaching the witness).
