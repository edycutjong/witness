Witness is a Python CLI and MCP server built on Relate.

When an agent answers from a graph, Witness hands back a small graph that reproduces the answer, and proves that deleting any one of its relationships changes the answer.

Every trial is a Relate transaction, and the witness is one .rl file you open with plain relate. Built for the Relate by Neo4j hackathon.

How it uses Relate · mode, reason, capabilities

Every trial is a Relate transaction.

Mode
Single file (.rl). Reductions run on a file-backed scratch copy in a temp dir; the committed source is copied byte for byte, never opened for writing, and its SHA-256 is checked unchanged after every run.
Why this mode
The unit of evidence is a file. One .rl per witness can be committed, handed over and re-run by a reviewer with relate alone, with no server. A directory store is many files; :memory: disappears when the process ends and cannot be inspected.
What the graph models
The air-routes network by Kelvin Lawrence (Apache-2.0): 3,748 nodes and 57,645 relationships, (:Airport)-[:HAS_ROUTE]->(:Airport), (:Airport)-[:IN_COUNTRY]->(:Country) and (:Airport)-[:ON_CONTINENT]->(:Continent) (data/SOURCE.md).

Verify it yourself · on your machine, with your own Relate

Don’t take the page’s word. Run it.

  1. 1

    Run the whole path

    git clone https://github.com/edycutjong/witnesscd witnessuv run witness demo

    Expect22 of 22 change the answer, a last line that starts VERIFIED, and exit 0.

    Needs uv. The committed graph is copied, never modified; the output goes to out/. The recorded run reports 5.78 s end to end on an Apple M1 Max (evidence/demo-2026-11-24.txt). With a relate CLI other than v1.0.1 on your PATH the first lines say the CLI cross-check is skipped; the Python checks and the result are the same.

  2. 2

    Re-prove the committed witness

    uv run witness check witnesses/two-hub.rl

    Expect22 of 22 change the answer, then VERIFIED, exit 0. Exit 1 would mean not verified.

    One fresh copy of the witness per probe; nothing is shared with the reduction.

  3. 3

    Re-run it with plain Relate

    relate query --database witnesses/two-hub.rl --read-only \ --param country=MX --param dest=MEX \ < queries/two-hub.cypher

    Expectthe same 4 airports the full graph gives: PBC, QRO, TLC, UPN.

    Needs the Relate CLI (checked with v1.0.1 and v1.3.0, evidence/relate-1.3.0-2026-11-27.txt). No Witness code runs: the witness is an ordinary .rl file.

  4. 4

    Ask it something else

    uv run witness why -f queries/examples/fewest-flights.cypher --param from=JOG --param to=KEFuv run witness why -f queries/examples/longest-nonstop.cypher --param from=CGKuv run witness why -f queries/examples/domestic-only.cypher --param country=IS

    Expect3 of 3 change the answer, 2 of 2 change the answer and 4 of 4 change the answer, each ending VERIFIED, exit 0.

    Three other query shapes on the same graph: a path question (what is the smallest number of flights that gets you from JOG to KEF), a top-k with ORDER BY + LIMIT (which two nonstop flights out of CGK are the longest) and an EXISTS / NOT EXISTS pair (which airports of IS have flights, but none that leave the country). Or bring your own graph: uv run witness why -f Q.cypher --store YOUR.rl.

  5. 5

    Run the tests

    uv run pytest --cov=witness

    Expect569 passed and 100% line and branch coverage; 3 more need a Neo4j server and skip without one.

    CI and deterministic replay, not the product path.

Honest limitations

What the stamp does not say.

  1. 1

    Verified is about the evidence, not the query

    Exit 0 says the witness is deletion-minimal for its predicate. It does not say the query asks the right question; the repro of a wrong answer is verified too.

  2. 2

    Supports, not guards

    A witness holds what reproduces the rows it has, not what keeps other rows out. In the full graph 35 single relationships each keep another airport out of the headline answer, and 34 of them are not in the witness (evidence/full-graph-sensitivity.json).

  3. 3

    Deletion-minimal, not smallest

    No single remaining relationship can be removed without changing the answer; a smaller witness may exist.

  4. 4

    Its own answer, on its own file

    Because a query with NOT EXISTS or aggregation is not monotone, a witness does not prove that every graph containing it gives the same answer. It also leaves out true facts the answer does not need: MEX has no country link in witnesses/two-hub.rl.

  5. 5

    Read-only Cypher only, with no clock or randomness

    Witness refuses writes, procedures, clocks and randomness (exit 2) rather than guess. Dependence on storage order is caught by a heuristic (the same answer from a store built in reverse order), not proven absent.

  6. 6

    Answers that rest on thousands of facts do not shrink

    A count over the whole graph ran to the default cap of 20,000 trials (18 minutes here) and exited 3, NOT verified, with 38,521 relationships left (evidence/other-queries.json).

  7. 7

    One graph (a public air-routes dataset, Apache-2.0)

    The headline query, three more cases and three more query shapes. The one mistaken query was written for the case; the engine disagreement is observed, and only on Relate 1.0.1, 1.1.0 and 1.2.0. The Neo4j comparison is one machine, one query, one graph; it measures this setup (Docker VM, Bolt round trip), not a limit of Neo4j.
